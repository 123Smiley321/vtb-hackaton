# Антифрод-система для выявления мошеннических операций (роль P2)

## О проекте

Проект представляет собой прототип интеллектуальной антифрод-системы для выявления подозрительных финансовых операций с использованием методов машинного обучения.

Основная задача системы - оценивать риск мошенничества при совершении перевода, выявлять потенциально подозрительные операции и предоставлять объяснения результатов модели. Решение предполагает совместное использование ML-скоринга, законодательных проверок и дополнительных сценариев взаимодействия с клиентом.

В рамках проекта исследуется датасет IEEE-CIS Fraud Detection, строится модель классификации мошеннических транзакций, анализируется качество её работы и реализуется подход к интерпретации предсказаний с помощью SHAP.

## Задачи проекта

- Исследование и предварительный анализ данных IEEE-CIS Fraud Detection.
- Объединение транзакционных данных и информации об устройствах.
- Построение временного разделения данных для приближения к реальному банковскому сценарию.
- Разработка исторических признаков новизны устройства и платёжной карты.
- Обучение модели LightGBM для бинарной классификации транзакций.
- Оценка качества модели с использованием метрик классификации.
- Подбор порога классификации с учётом допустимого уровня ложноположительных срабатываний.
- Интерпретация отдельных предсказаний с помощью SHAP.
- Разработка архитектуры технических блоков антифрод-системы.

## Датасет

Для экспериментов используется открытый набор данных **IEEE-CIS Fraud Detection**, содержащий информацию о транзакциях и связанных с ними характеристиках идентификации.

Используются два исходных файла:

| Файл | Размер | Содержание |
|---|---:|---|
| `train_transaction.csv` | 590 540 строк, 394 столбца | Данные о транзакциях |
| `train_identity.csv` | 144 233 строки, 41 столбец | Дополнительные сведения об устройствах и идентификации |

Таблицы объединяются по `TransactionID` с помощью `LEFT JOIN`. После объединения получается единый датасет размером **590 540 строк и 434 столбца**.

Целевая переменная — `isFraud`:
- `0` — легальная операция;
- `1` — мошенническая операция.

### Баланс классов

| Класс | Количество | Доля |
|---|---:|---:|
| Легальные операции | 569 877 | 96,501% |
| Мошеннические операции | 20 663 | 3,499% |
| Всего | 590 540 | 100% |

Датасет характеризуется выраженным дисбалансом классов: мошеннические операции составляют около 3,5% всех наблюдений.

В данных также присутствует значительное количество пропусков, особенно в признаках группы `id_*` и информации об устройстве. Например, `DeviceInfo` содержит около 79,91% пропусков, а `DeviceType` — около 76,16%.

## Предварительная обработка и формирование признаков

В процессе подготовки данных выполняются следующие действия:

1. Проверка уникальности `TransactionID` в исходных таблицах.
2. Объединение транзакционных и идентификационных данных.
3. Сортировка операций по `TransactionDT`.
4. Обработка категориальных признаков и пропущенных значений.
5. Исключение технического идентификатора, целевой переменной и временного поля из входных признаков модели.

Дополнительно формируются исторические признаки новизны:

| Признак | Описание |
|---|---|
| `device_new` | Показывает, впервые ли встречается устройство |
| `device_prev_count` | Количество предыдущих появлений устройства |
| `card_new` | Показывает, впервые ли встречается комбинация карточных признаков |
| `card_prev_count` | Количество предыдущих появлений комбинации карты |

При расчёте исторических признаков учитываются только события, произошедшие раньше текущей транзакции. Целевая переменная `isFraud` при их построении не используется.

После подготовки данных для модели используется **435 признаков**, из которых **31 категориальный**.

## Разделение данных

Для предотвращения утечки информации применяется временное разделение по `TransactionDT`.

| Выборка | Количество операций | Мошеннические операции | Доля мошенничества |
|---|---:|---:|---:|
| Train | 354 324 | 11 988 | 3,383% |
| Validation | 118 108 | 4 611 | 3,904% |
| Test | 118 108 | 4 064 | 3,441% |

- Train (60%) используется для обучения модели.
- Validation (20%) используется для контроля качества, ранней остановки и выбора порога.
- Test (20%) используется для итоговой независимой оценки качества.

Тестовая выборка не используется для подбора порога классификации.

## Модель машинного обучения

Для выявления мошеннических операций используется **LightGBM** — алгоритм градиентного бустинга на деревьях решений.

Основные параметры обучения:

| Параметр | Значение |
|---|---:|
| Objective | binary |
| Metric | AUC |
| Learning rate | 0.03 |
| Num leaves | 63 |
| Max depth | -1 |
| Min child samples | 100 |
| Feature fraction | 0.8 |
| Bagging fraction | 0.8 |
| Bagging frequency | 1 |
| L2 regularization | 1.0 |
| Максимальное число итераций | 3000 |
| Early stopping | 150 |
| Seed | 42 |

Лучшая итерация обучения — **703**.

Модель возвращает оценку риска мошенничества для каждой операции. Для преобразования оценки в бинарный сигнал используется порог классификации.

### Интерпретация метрик

- **Precision** — доля действительно мошеннических операций среди всех операций, отмеченных моделью как подозрительные.
- **Recall** — доля обнаруженных мошеннических операций среди всех фактически мошеннических операций.
- **FPR** — доля легальных операций, ошибочно отмеченных моделью.
- **ROC-AUC** — способность модели ранжировать мошеннические и легальные операции при различных порогах.
- **PR-AUC** — качество обнаружения положительного класса с учётом Precision и Recall.
- **Доля ложных сигналов** — доля ложноположительных результатов среди всех сигналов модели.

### Матрица ошибок

| Фактический класс | Прогноз: легальная | Прогноз: мошенничество |
|---|---:|---:|
| Легальная операция | 112 583 | 1 461 |
| Мошенническая операция | 2 285 | 1 779 |

На тестовой выборке модель обнаружила 1 779 мошеннических операций и пропустила 2 285. При этом 1 461 легальная операция получила ложный сигнал.

Целевой FPR в 1% задавался на validation, однако на test фактический показатель составил 1,28%. Это показывает, что ограничение, достигнутое на валидационной выборке, не гарантирует идентичный результат на последующем временном периоде.

### Анализ сумм транзакций

На тестовой выборке:

| Показатель | Значение |
|---|---:|
| Общая сумма мошеннических операций | 609 934,34 |
| Сумма обнаруженных мошеннических операций | 210 642,20 |
| Сумма пропущенных мошеннических операций | 399 292,14 |
| Полнота обнаружения по сумме | 34,54% |

Сумма обнаруженных мошеннических операций рассчитана при условном предположении, что каждая правильно выявленная операция полностью останавливается.

**Важно:** значения приведены в исходных единицах `TransactionAmt`. Валюта датасета не подтверждена как рубли, поэтому эти суммы не являются рассчитанным предотвращённым ущербом банка.

Экономическая оценка стоимости ошибок требует дополнительных согласованных параметров, в том числе стоимости ложного сигнала и доли потерь от пропущенного мошенничества.

## Интерпретация модели с помощью SHAP

Для объяснения отдельных предсказаний применяется SHAP (SHapley Additive exPlanations).

Метод позволяет определить, какие признаки повлияли на оценку риска конкретной операции и в каком направлении.

- Положительное значение SHAP повышает оценку риска мошенничества.
- Отрицательное значение SHAP снижает оценку риска.
- Для каждого случая выделяются три наиболее значимых признака по абсолютной величине вклада.

### Примеры объяснения предсказаний

| TransactionID | Класс случая | Оценка риска | Три наиболее значимых признака |
|---|---|---:|---|
| 3459504 | TP | 0.7098 | C1, V258, DeviceInfo |
| 3459510 | TP | 0.6238 | C1, C13, C14 |
| 3459708 | FP | 0.1889 | C14, id_30, R_emaildomain |

В первых двух примерах модель правильно выявила мошеннические операции. Третий пример представляет собой легальную операцию, ошибочно отмеченную как подозрительную.

Для этих случаев формируются два уровня объяснений:

1. **Для клиента** — понятное предупреждение с рекомендацией проверить получателя и обстоятельства перевода.
2. **Для оператора контакт-центра** — оценка риска, три наиболее значимых признака, значения SHAP и рекомендации по дополнительной проверке.

Анонимизированные признаки `V*`, `C*` и `id_*` не интерпретируются как доказательство мошенничества. Их точный бизнес-смысл в рамках эксперимента не установлен. Тексты предупреждений являются демонстрационными сценариями, а не готовыми банковскими шаблонами.

## Техническая архитектура антифрод-системы

Предлагаемая архитектура состоит из шести последовательных блоков:

1. **Сбор сигналов** — получение данных транзакции, сессии, устройства, получателя и доступных внутренних и внешних источников.
2. **Правила 161-ФЗ** — проверка операции на соответствие законодательным требованиям.
3. **ML-скоринг** — оценка риска мошенничества с помощью LightGBM и объяснение факторов срабатывания через SHAP.
4. **Выбор реакции** — определение дальнейшего сценария обработки операции.
5. **Разбор и контакт-центр** — дополнительная проверка спорных операций и уточнение обстоятельств перевода.
6. **Обратная связь в разметку** — использование результатов проверок для обновления обучающих данных и последующего улучшения модели.

### Сценарии реакции

В зависимости от результата законодательных проверок и оценки риска моделью могут применяться следующие сценарии:

- пропуск операции;
- предупреждение клиента;
- дополнительное подтверждение;
- дополнительная проверка;
- передача спорного случая на разбор;
- приостановка операции при наличии предусмотренных законом оснований.

### Онлайн-признаки и ночной профиль

Архитектура предусматривает разделение информации на две группы:

- **Онлайн-признаки** — сумма и время операции, текущая сессия, устройство, получатель и доступные данные банка. Используются для первичной оценки риска.
- **Ночной профиль клиента** — история предыдущих операций, частота переводов, привычное поведение и ранее используемые устройства. Обновляется при последующей обработке накопленных данных и может поступать с задержкой до 24 часов.

Текущий перевод оценивается по доступным онлайн-признакам. Система не должна ожидать обновления ночного профиля.

### Отказоустойчивость

При недоступности ML-сервиса система переходит на резервный сценарий с использованием доступного слоя правил 161-ФЗ. Это позволяет продолжить предусмотренную обработку операций без полной остановки процесса.

Целевой показатель времени онлайн-обработки — **менее 300 мс** на принятие решения. Разбор операций контакт-центром не входит в этот временной интервал.

Архитектура является проектным описанием целевого процесса, а не утверждением о том, что все перечисленные банковские компоненты уже реализованы в программном прототипе.

## Ограничения эксперимента

- Эксперименты выполняются на открытом датасете IEEE-CIS, который не является реальным набором операций ВТБ.
- В датасете присутствует значительное количество пропусков и анонимизированных признаков.
- Бизнес-интерпретация ряда признаков не установлена.
- Целевой FPR на validation не гарантирует аналогичный показатель на test.
- Ложноположительное срабатывание модели не означает автоматическую блокировку операции.
- Суммы `TransactionAmt` нельзя интерпретировать как рубли без подтверждения валюты.
- Описанная архитектура включает проектные компоненты, которые не следует считать реализованными только на основании исследовательского ноутбука.

## Результат работы

В рамках исследовательской части проекта подготовлен временной эксперимент с моделью LightGBM на датасете IEEE-CIS, реализованы исторические признаки новизны устройства и карты, рассчитаны метрики качества на независимой тестовой выборке и исследованы объяснения отдельных предсказаний с помощью SHAP.

Дополнительно разработана схема интеграции ML-скоринга в общую антифрод-архитектуру с законодательными проверками, выбором реакции, контакт-центром и обратной связью для последующего улучшения модели.
